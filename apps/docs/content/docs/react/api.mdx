# React API

Everything exported from `@lovo/matter-react`. This page is hand-written for the launch milestone; a generated reference from TypeDoc lands post-launch.

## `<ShaderScene>`

The scene wrapper. Owns the WebGPU canvas, creates the renderer, runs the scheduler. Every Tier 1 Matter component must render inside one.

```tsx
import { ShaderScene } from '@lovo/matter-react'

<ShaderScene
  style={{ height: '100vh' }}
  dprMax={2}
  pauseOffscreen
>
  <Aurora />
</ShaderScene>
```

**Props:**

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `dprMax` | `number` | `2` | Maximum device pixel ratio to render at. |
| `gamut` | `'auto' \| 'srgb' \| 'p3'` | `'auto'` | Output color gamut. `'auto'` detects via `(color-gamut: p3)` and re-resolves when the window moves to another display. See [the color guide](/guides/color#gamut--what-the-output-can-hold). |
| `pauseOffscreen` | `boolean` | `true` | Whether to pause rendering when the canvas leaves the viewport. |
| `style` | `CSSProperties` | — | Forwarded to the canvas container. |
| `className` | `string` | — | Forwarded to the canvas container. |
| `children` | `ReactNode` | — | One or more Matter components. |
| `onError` | `(error: MatterError) => void` | — | Called once if renderer init fails (e.g. no GPU backend). Receives a `MatterError` with `code: 'renderer-init'` and the original error on `.cause`. |

## `useShaderMaterial`

The lower-level hook for users who already own a `<Canvas>` from `@react-three/fiber`. Use this when you want Matter primitives inside your own r3f scene — see [Three / r3f](/react/guides/three-r3f).

```tsx
import { useShaderMaterial } from '@lovo/matter-react'
import { uv } from 'three/tsl'
import { fractalNoise } from '@lovo/matter'

function Plane() {
  const material = useShaderMaterial({
    color: fractalNoise(uv()),
  })
  return <mesh material={material}><planeGeometry /></mesh>
}
```

## Input hooks

All three return signal-shaped objects compatible with [animation props](/guides/animation):

- **`useCursor()`** → `CursorSignal` with `value` in `[0, 1]` normalized to the canvas bounding rect.
- **`useScroll()`** → `ScrollSignal` with normalized scroll progress for the page.
- **`useResize()`** → `ResizeSignal` with current canvas dimensions in pixels.

All three are Strict-Mode-safe (no leaked listeners on dev double-mount) and must be called inside a `<ShaderScene>` subtree so they can plumb to the canvas.

## `useAnimatableUniform`

Low-level animation glue. Pass an animatable prop — a static value or a signal — and get back a stable TSL uniform node that tracks it:

```tsx
import { useAnimatableUniform, type AnimatableProp } from '@lovo/matter-react'

function Inner({ reach }: { reach: AnimatableProp<number> }) {
  const reachUniform = useAnimatableUniform(reach)
  // reachUniform.value updates on every signal change — no React re-render
}
```

The returned node keeps its identity for the component's lifetime, so a material can capture it at compile time; signal updates write straight to `.value` and never touch React. Tier 1 components call this internally for their public props. You only need it when wiring up a custom shader.

## `useAnimatablePoint`

The `[x, y]` sibling, for props like `center`. Same contract — static pair or signal in, one stable `vec2` uniform out, backed by a single `Vector2` mutated in place:

```tsx
import { useAnimatablePoint, type AnimatableProp } from '@lovo/matter-react'

function Inner({ center }: { center: AnimatableProp<readonly [number, number]> }) {
  const centerUniform = useAnimatablePoint(center, { screenOrigin: true })
  // centerUniform.value is a Vector2, mutated in place on every change
}
```

`screenOrigin: true` treats the incoming pair as a screen-style point — `[0, 0]` at the top-left, y growing downward, like CSS — and converts it to uv space, where v grows upward. Both coordinates are expected normalized to `[0, 1]`: the conversion is just `v = 1 - y`, with no scaling, so pixel coordinates won't land where you expect. It's off by default.

## `useAnimatableSpeed`

The animation glue behind every registry component's `speed` prop. It does not return a speed uniform — it returns a scalar **phase** uniform, integrating speed over time on the CPU:

```tsx
import { useAnimatableSpeed, type AnimatableProp } from '@lovo/matter-react'

function Inner({ speed }: { speed: AnimatableProp<number> }) {
  const phaseUniform = useAnimatableSpeed(speed)
  // phaseUniform.value grows by speed x delta each frame, scaled by reduced motion
}
```

Each scheduler tick adds `speed × delta` (scaled for `prefers-reduced-motion`) to a running total, rather than multiplying elapsed time by speed. That distinction matters: a product form re-evaluates the whole elapsed history whenever speed changes, so the pattern visibly snaps; the integral form only changes the growth rate, so a speed change shifts tempo smoothly from wherever the pattern already is. Accepts a static number or an animation signal, same as the other animatable hooks.

## `<FallbackBoundary>`

Renders fallback content when WebGPU is unavailable or initialization fails. Wrap any Matter subtree:

```tsx
<FallbackBoundary fallback={<img src="/hero-fallback.png" />}>
  <ShaderScene>
    <Aurora />
  </ShaderScene>
</FallbackBoundary>
```

See [SSR and fallbacks](/react/guides/ssr-and-fallbacks) for the full pattern.

## `<ShaderPoster>`

A static stand-in shown until the shader's first content frame is on screen, and again whenever the renderer is rebuilt. If the renderer never initializes, the poster simply stays up.

`poster` takes any node, not a URL — it renders inside an absolutely-positioned wrapper covering the boundary, so a `next/image` with `fill` works as-is and a plain `<img>` only needs width and height at 100%.

Imported from its own entry point, which has no path to three and so server-renders:

```tsx
import { ShaderPoster } from '@lovo/matter-react/poster'

<ShaderPoster poster={<img alt="" src="/hero-poster.avif" style={{ width: '100%', height: '100%' }} />}>
  <ShaderScene>
    <Aurora />
  </ShaderScene>
</ShaderPoster>
```

## `useDisplayGamut`

Resolves a gamut preference to what the display can actually show. Pass `'srgb'` or `'p3'` to fix it, or `'auto'` to query `(color-gamut: p3)` and re-resolve when the window moves to another monitor.

```tsx
import { useDisplayGamut } from '@lovo/matter-react/gamut'

const gamut = useDisplayGamut('auto') // 'srgb' | 'p3'
```

Also on its own three-free entry point — the hook only asks `matchMedia` a question, and returns `'srgb'` when there's no `window`, so it is safe during a server render. See [SSR and fallbacks](/react/guides/ssr-and-fallbacks#the-three-free-subpaths).

## `useStaticSceneHint`

Marks the scene as static — renders once on mount, then only on prop / signal changes. Use for decorative shaders without time-based animation.

```tsx
function Hero() {
  useStaticSceneHint(true)
  return <LinearGradient />
}
```

## `useShaderContext`

Returns the current `ShaderContextValue` — renderer, scheduler, canvas refs. Internal-ish; you rarely need it directly. Tier 1 components use it under the hood.

## `<ShaderMonitor>`

Dev overlay showing FPS, active component count, scheduler state, and per-component frame budget. Not for production:

```tsx
{process.env.NODE_ENV === 'development' && <ShaderMonitor anchor="bottom-right" />}
```

**Props:**

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `anchor` | `'top-left' \| 'top-right' \| 'bottom-left' \| 'bottom-right'` | `'bottom-right'` | Where to position the overlay. |
