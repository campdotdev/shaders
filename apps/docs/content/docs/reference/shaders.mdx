# Engine API

This page lists the engine half of `@camp-dev/shaders`: the TSL primitives, the runtime, the inputs, and reduced-motion-gated time. The React half is on the [React API](/react/api) page. A generated TypeDoc reference replaces this hand-written page post-launch.

## Tier 2 primitives

TSL building blocks for writing shader expressions, all exported from the package root.

- `colorRamp(t, stops)` — multi-stop color gradient sampled at `t` ∈ [0, 1].
- `simplexNoise(uv, opts?)` — single-octave 2D value noise.
- `fractalNoise(uv, opts?)` — fractional Brownian motion. Octave-stacked noise with `octaves`, `lacunarity`, `gain` (a number, or a uniform node for a live dial), and `fold` (`'none' | 'smooth' | 'sharp'` turbulence folding).
- `voronoi(uv, opts?)` — distance-to-nearest-feature noise.
- `quantize(value, steps, threshold?)` — posterize a value to discrete steps, component-wise for vecs. `steps` can be a uniform node (animatable), and `threshold` replaces the built-in 0.5 rounding point — pass an ordered-dither threshold to dither.
- `ditherThreshold(pattern, cellCoord)` — threshold maps for ordered dithering: `'bayer-2x2'`/`'bayer-4x4'`/`'bayer-8x8'`, halftone `'dots'`/`'lines'`, and `'white-noise'`/`'blue-noise'`/`'gradient-noise'`. Powers the `<Dither>` component. Not the same job as the scene's automatic output dither, which is invisible anti-banding noise — this one is the loud, artistic kind.
- `signedDistanceFieldCircle(uv, radius, center)` — signed-distance field for a circle. Negative inside, positive outside.
- `displace(uv, offset)` — UV displacement helper.
- `cursorRipple(uv, cursor, opts?)` — cursor-following ripple displacement (used by `<DotField>`).

### Strands

Four primitives draw strands: fine curves of light that are a mesh, not a fragment shader. They are for Mode 2, where your own camera draws them. [Three / r3f](/react/guides/three-r3f#draw-strands-in-your-scene) shows them together.

- `createStrandGeometry({ strands, samples })` — a `BufferGeometry` of strips, one per strand, with `samples` points along each. It has no positions. Each vertex stores four floats: `strandAcross`, `strandSeed`, `strandAlong`, and `strandSide`. Dispose it when you are done.
- `strandAttributes()` — those four attributes as float nodes: `across` (the strand's place among the others, 0 to 1), `seed` (a random number per strand, 0 to 1), `along` (0 to 1 down the strand), and `side` (-1 or 1, the edge of the strip).
- `extrudeStrand(path, { strandWidth })` — widens a path into a strip `strandWidth` CSS pixels thick at any distance from the camera. `path` is a function `(along, across, seed) => vec3` that returns a point in the mesh's own space. It must depend only on its inputs and on uniforms. Returns `position`, a clip-space vec4 for the material's vertex node, and `distance`, the signed distance in CSS pixels from the strand's center line.
- `strandProfile(distance, strandWidth)` — a Gaussian falloff across a strand: 1 on the center line and about 0 at the edges. Below a half-width of `MIN_STRAND_HALF_WIDTH` (1.5 CSS pixels), a strand keeps that width and dims.

## Layering and `elapsedTime`

Shaders sits on top of Three.js's TSL. Pure TSL primitives (`uv`, `vec2`, `vec3`, `vec4`, `uniform`, `mix`, `smoothstep`, `mod`, `sin`, `cos`, `length`, `dot`, `normalize`, `max`, `min`) live in `three/tsl` — import them directly from there:

```ts
import { uv, vec3, uniform, mix } from 'three/tsl'
```

Shaders exports one TSL node of its own: **`elapsedTime`**. It's the TSL built-in `time` multiplied by an engine-owned reduced-motion scale uniform, so every component that animates against `elapsedTime` from `@camp-dev/shaders` automatically respects `prefers-reduced-motion` and the policy override set via `setReducedMotionPolicy`.

```ts
import { elapsedTime } from '@camp-dev/shaders'
//  → equivalent to three/tsl's `time.mul(reducedMotionScale)`

// If you specifically want raw uncapped time (e.g. a debug overlay):
import { time as rawTime } from 'three/tsl'
```

> **Migrating from 0.1.x?** Before 0.2.0, `@camp-dev/shaders` re-exported the TSL primitives listed above as a convenience. They're gone in 0.2.0 — replace `import { vec3, uv, … } from '@camp-dev/shaders'` with `import { vec3, uv, … } from 'three/tsl'`. `elapsedTime` (named `time` before 0.5.0) is the only carry-over and stays imported from `@camp-dev/shaders`.

## Runtime

- **`createRenderer(canvas, opts?)`** → `Promise<GpuRenderer>`. Allocates a WebGPU renderer. Used internally by `<ShaderScene>`; you rarely call it directly. `depth: true` gives the canvas a depth buffer on WebGPU, for a scene of your own where a nearer mesh hides a farther one. It defaults to `false`.
- **`FrameScheduler`** — the render-frame coordinator. Components register as `SchedulerClient`s; the scheduler ticks them when their scene is visible and not reduced-motion-paused.
- **Visibility / intersection watchers** — `createVisibilityWatcher()`, `createIntersectionWatcher()`. Low-level utilities behind the offscreen-pause behavior.

## Inputs

- **`CursorInput`** — framework-agnostic cursor source. `useCursor()` wraps it; in Mode 2 or non-React contexts, you instantiate it directly.

## Reduced motion

- **`setReducedMotionPolicy(policy)`** — set globally to `'auto'`, `'off'`, `'slow'`, or `'paused'`. See [the performance guide](/guides/perf#honor-reduced-motion-with-setreducedmotionpolicy).
- **`getReducedMotionPolicy()`** — read the current policy.
- **`getReducedMotionTimeScale()`** — get the current animation time scale (0, 0.3, or 1).
- **`createReducedMotionWatcher()`** — subscribe to policy changes.

## Color math — `@camp-dev/shaders/color`

CPU-side color conversion, run once in JavaScript when a prop is parsed. The GPU only ever sees the resulting numbers.

These are also exported from the root entry, but prefer the subpath: it has no path to three, so it can be imported during a server render, where the root entry cannot. See [SSR and fallbacks](/react/guides/ssr-and-fallbacks#the-three-free-subpaths).

```ts
import { parseColorString, linearSrgbToOklch } from '@camp-dev/shaders/color'
```

- `parseColorString(input)` → extended linear-sRGB. Accepts `#rrggbb`, `#rrggbbaa` (alpha dropped), `oklab(L a b)`, and `oklch(L C H)`. Throws on anything else, including components that aren't numbers.
- `parseOklchString(input)` → `[l, c, h]`, the numbers as written, with no conversion. Takes the same `oklch(L C H)` syntax as `parseColorString`, so a color picker can set its sliders from a typed value without drifting it. The hue is not wrapped into [0, 360).
- `oklabToLinearSrgb(l, a, b)` / `oklchToLinearSrgb(l, c, h)` → extended linear-sRGB. Not clamped: colors outside sRGB come back with channels below 0 or above 1.
- `linearSrgbToOklch(r, g, b)` → `[l, c, h]`, hue normalized to [0, 360).
- `linearSrgbToLinearDisplayP3(r, g, b)` → extended linear Display-P3.
- `oklchInGamut(l, c, h, gamut)` → whether a display of that gamut can show the color.
- `oklchToGamut(l, c, h, gamut)` → `[l, c, h]` in OKLCH. The nearest color the gamut can show, found by shedding chroma while holding lightness and hue unchanged.
- `srgbChannelToLinear(channel)` / `linearChannelToSrgb(channel)` — the sRGB transfer curve, one channel at a time.
