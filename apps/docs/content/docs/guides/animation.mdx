# Animation

Shaders doesn't ship its own animation library. Component props that need to animate accept either a static value or a **signal** — anything with a `get()` and `on('change', callback)` shape. Motion's `MotionValue`, Jotai atoms with a wrapper, custom signal libraries — they all work, because Shaders just reads the current value and subscribes to changes.

## The signal contract

A signal is any object shaped like:

```ts
interface AnimatableSignal<T> {
  get(): T
  on(event: 'change', callback: (value: T) => void): () => void
}
```

When a Shaders component receives a signal as a prop, it:

1. Reads `signal.get()` to seed the uniform — on mount, and again whenever the signal is swapped for another.
2. Subscribes with `on('change', …)` and writes each new value into the GPU uniform.
3. Unsubscribes on unmount.

The animation engine doesn't run on the CPU per-frame — values flow straight into the uniform and the GPU does the rest.

## With Motion

[Motion](https://motion.dev) (formerly Framer Motion) is the canonical integration. `MotionValue<number>` and `MotionValue<string>` already implement the signal shape, so you can pass them directly:

```tsx
import { useMotionValue, useTransform, useScroll } from 'motion/react'
import { ShaderScene } from '@mattermix/shaders-react'
import { DotField } from '@/components/shaders/dot-field'

export function Hero() {
  const { scrollYProgress } = useScroll()
  const reach = useTransform(scrollYProgress, [0, 1], [0.1, 0.6])

  return (
    <ShaderScene style={{ height: '100vh' }}>
      <DotField reach={reach} />
    </ShaderScene>
  )
}
```

`reach` is a `MotionValue<number>` — Shaders subscribes to it and pipes updates into the `reach` uniform.

## Built-in input signals

Shaders ships three React hooks that produce ready-to-use signals — they handle the canvas-aware math and Strict Mode lifecycle correctly:

- `useCursor()` — returns a `CursorSignal` with `value` ([0,1] across the canvas rect, not the viewport).
- `useScroll()` — returns a `ScrollSignal` with normalized scroll progress.
- `useResize()` — returns a `ResizeSignal` with current canvas dimensions.

```tsx
import { ShaderScene, useCursor } from '@mattermix/shaders-react'

function App() {
  return (
    <ShaderScene>
      <Cursor />
    </ShaderScene>
  )
}

function Cursor() {
  const cursor = useCursor()
  return <DotField cursor={cursor} />
}
```

`useCursor()` must be called inside a `<ShaderScene>` so it can plumb to the canvas; it normalizes coordinates to the canvas bounding rect.

## Animating any uniform

If you're wiring up a custom shader, `useAnimatableUniform` is the lower-level escape hatch — pass it a static value or a signal and it returns a TSL uniform node that tracks it. `useAnimatablePoint` does the same for `[x, y]` pairs like `center`. See [the React API](/react/api) for the full signatures.

## What Shaders does NOT ship

- No built-in spring / keyframe / timeline library.
- No `<motion.div>`-style component primitives.
- No state machine glue.

Bring your own animation library. Shaders just consumes signals.
